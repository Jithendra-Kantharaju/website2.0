# Jithendra Kantharaju — engineering portfolio

A responsive portfolio for DevOps, Cloud, SRE, Forward Deployed Engineer, and AI Engineer opportunities. Built with the existing Next.js 15 App Router, React 19, Tailwind 3, and EmailJS architecture.

## Local development

```sh
npm install
npm run dev
```

## Production checks and preview

```sh
npm run lint
npm run typecheck
npm run build
node scripts/serve-preview.mjs
```

Open http://127.0.0.1:3000. `npm start` also runs this local production preview. The project uses `output: 'export'`; its production artifact is `out/`. Serve that directory with a static host. `next start` does not serve a static export.

JavaScript is checked with TypeScript's `checkJs` and JSDoc-compatible inference; application files remain JavaScript/JSX. ESLint includes accessibility rules.

## Browser verification

Use Node 22 or newer. Start the static preview above, then launch an installed Chrome in headless mode with a dedicated temporary profile and `--remote-debugging-port=9333`. Run:

```sh
npm run verify:browser
```

The harness uses Chrome DevTools Protocol through Node's built-in WebSocket and the axe-core supplied by the existing accessibility lint dependency. It checks five viewport sizes, internal anchors, images, headings, the primary action, menu focus/Escape, form validation and intercepted success/error responses, reduced motion, and content without JavaScript. It samples a finite workflow animation under 4x CPU throttling. Screenshots and results go to ignored `artifacts/`.

EmailJS requests in browser verification are intercepted. No real email is sent. Throttled desktop results do not replace physical phone testing.

## Contact configuration

Retains the original EmailJS template fields: `from_name`, `from_email`, `message`, `to_name`.

Set these public identifiers in a local environment file before building:

- `NEXT_PUBLIC_EMAILJS_SERVICE_ID`
- `NEXT_PUBLIC_EMAILJS_TEMPLATE_ID`
- `NEXT_PUBLIC_EMAILJS_PUBLIC_KEY`

Never add private API keys. Without configuration, the form displays an inline explanation and a direct email link. The identifiers are intentionally embedded in the client build, as required by EmailJS.

## Content and assets

- `src/data/portfolio.js`: existing employment, education, skill, and certification records.
- `src/data/projects.js`: case studies, evidence links, diagram lanes, and scope limitations.
- `public/fonts/`: locally served Geist weights and SIL Open Font License.
- `public/social-card.png`: sharing image, generated by `node scripts/create-social-card.mjs`.
- Existing project imagery, certification badges, and background media remain in `public/`. Background frames and videos are no longer requested by the page.

There is no resume button because no resume PDF is present. Certification expiration and verification URLs have not been supplied; the site does not claim that every credential is active.

## Animation enhancement verification

The animation layer uses native WAAPI, CSS transitions, and IntersectionObserver without additional runtime dependencies. The current audit, timelines, changed-file inventory, and verification limits are in [docs/ANIMATION-PLAN.md](docs/ANIMATION-PLAN.md) and [docs/ANIMATION-REVIEW.md](docs/ANIMATION-REVIEW.md).

With Chrome on debugging port 9333 and the Next development server running at http://localhost:3000:

```sh
node scripts/verify-motion.mjs
```

This checks real intermediate hero states, one-time scroll reveals, sequential project workflows, packet interpolation, pause/replay, keyboard behavior, reduced motion, responsive overflow, layout shifts, and unchanged content-data hashes. The task's content baseline is saved in ignored artifacts/animation-content-baseline.json. On a clean checkout, establish a baseline before animation edits with `node scripts/verify-motion.mjs --write-baseline`. The general browser harness also supports PREVIEW_URL for checking the production export.
